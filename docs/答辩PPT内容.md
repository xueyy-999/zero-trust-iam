# 01. 研究内容简介

## 1.1 选题背景

### 国内外研究现状

**国内现状：**
- 以开源组件（Keycloak、OPA）为基础进行集成与定制
- 关注多协议兼容、策略动态调整与轻量化部署
- 不足：组件协同效率低，风险评估与授权决策的动态联动不足

**国外现状：**
- 以 NIST 零信任架构为核心
- 融合 OIDC/OAuth 2.0 与 ABAC/ReBAC 技术体系
- 不足：设计受特定生态约束，集成复杂，需本土化改进

### 传统安全模型的局限

- 边界安全模型：内网默认信任，外网默认不信任
- 问题：无法应对云计算、远程办公等新场景
- 风险：一旦边界被突破，内部资源完全暴露

### 零信任核心理念

- "永不信任，始终验证"（Never Trust, Always Verify）
- 每次访问都需要重新认证和授权
- 最小权限原则

## 1.2 研究目的与意义

### 研究目的

设计并实现一套基于零信任架构的身份认证与授权系统，构建"认证-评估-授权"一体化技术链路。

### 理论意义

- 深入理解零信任安全模型在动态访问控制中的实现机理
- 探索风险评估与策略执行的协同范式

### 实践意义

- 为中小型企业、科研平台提供完整且可复用的零信任 IAM 方案
- 提升系统在云环境下的安全防护与访问治理能力

## 2.2 风险评分算法（创新点）

### 多因素综合评分模型

基于 NIST 零信任架构标准，设计五因素风险评估算法：

| 风险因素 | 分值范围 | 检测目标 |
|----------|----------|----------|
| 失败登录次数 | 20-40 分 | 暴力破解攻击 |
| 地理位置异常 | 20 分 | 异地登录风险 |
| 特权操作 | 20 分 | 管理员权限滥用 |
| User-Agent 缺失 | 10 分 | 自动化攻击/爬虫 |
| 非工作时间访问 | 10 分 | 异常时间行为 |

### 风险等级划分

| 分数区间 | 风险等级 | 系统决策 |
|----------|----------|----------|
| 0-39 | 低风险 | 允许访问 |
| 40-69 | 中风险 | 需二次验证 |
| 70-100 | 高风险 | 拒绝访问 |

### 算法特点

- 可解释性：每个风险因素独立计算，结果可追溯
- 可扩展性：支持动态添加新的风险因素
- 实时性：平均响应时间 42ms

## 2.3 授权决策机制

### OPA ABAC 策略

基于属性的访问控制（Attribute-Based Access Control）：

**决策输入：**
- 用户属性：角色、部门、权限等级
- 资源属性：类型、敏感级别、所有者
- 环境属性：时间、地点、设备
- 风险分数：来自风险评估服务

**策略示例：**
```rego
# 允许条件：角色匹配 + 风险分数低于阈值
allow {
    input.roles[_] == "employee"
    input.action == "read"
    input.score < 70
}
```

# 03. 存在困难及问题

## 3.1 遇到的技术困难

| 困难 | 解决方案 |
|------|----------|
| OPA Rego 策略语言学习曲线陡峭 | 查阅官方文档，编写测试用例逐步验证 |
| OIDC 协议流程复杂 | 本地模拟完整流程，分步调试 |
| 组件间协同效率优化 | 异步处理 + 并行调用 |

## 3.2 当前系统局限

1. **风险评分**：基于规则引擎，未引入机器学习模型
2. **设备识别**：User-Agent 检测较为简单，缺乏精确的设备指纹
3. **认证方式**：仅支持 OIDC，未实现多因素认证（MFA）

## 3.3 后续改进方向

1. **智能化**：引入机器学习进行用户行为分析
2. **多因素认证**：集成短信/TOTP 二次验证
3. **设备指纹**：实现更精确的设备识别机制
4. **可视化监控**：集成 Prometheus + Grafana 监控面板
