## 场景一：正常访问放行

> **演示目标**：展示系统在低风险、合规情况下的自动放行机制。

### 操作步骤

打开 Web Portal 首页，填写以下参数：

| 字段 | 值 | 说明 |
|------|-----|------|
| 用户ID | `user_001` | 模拟普通员工 |
| 角色 | `employee` | 员工角色，有订单读取权限 |
| 资源 | `orders` | 请求访问订单数据 |
| 操作 | `read` | 只读操作 |
| IP | `10.2.5.100` | 内网IP段 |
| 地理位置 | `CN` | 中国境内 |
| 失败登录次数 | `0` | 无异常登录记录 |

点击「发起访问控制评估」。

### 预期结果

- 显示 **ACCESS GRANTED（访问允许）**
- 风险评分：**0-10 分**（低风险，绿色进度条）
- OPA 策略判定：**Allow**

### 讲解要点

```
这是一个典型的正常访问场景。
用户身份合法、权限匹配、环境无异常，系统自动放行。
风险评分接近零，说明当前上下文完全可信。
```

## 场景二：权限不足拦截（ABAC）

> **演示目标**：展示 OPA 策略引擎如何基于属性（角色、资源、操作）进行细粒度访问控制。

### 操作步骤

回到首页，修改参数：

| 字段 | 值 | 说明 |
|------|-----|------|
| 用户ID | `user_002` | 另一个用户 |
| 角色 | `intern` | 实习生角色 |
| 资源 | `financial` | 财务报表（敏感数据） |
| 操作 | `write` | 写入操作 |
| 其他 | 保持默认 | 环境参数正常 |

点击提交。

### 预期结果

- 显示 **ACCESS DENIED（访问拒绝）**
- 风险评分：**很低**（环境本身是安全的）
- OPA 策略判定：**Deny**

### 讲解要点

```
注意看，风险评分很低，说明环境没有问题。
但访问依然被拒绝，这是因为 OPA 策略层做了拦截。

实习生角色没有财务数据的写入权限，这是硬性的权限边界。
即使环境再安全，没有权限就是不能访问。

这体现了零信任的「最小权限原则」。
```

## 场景三：高风险环境拦截

> **演示目标**：展示风险引擎如何根据环境上下文动态计算风险分数，并触发拦截。
>
> **核心亮点**：这是本系统区别于传统 RBAC 的关键能力。

### 操作步骤

回到首页，使用「合法用户 + 高风险环境」组合：

| 字段 | 值 | 说明 |
|------|-----|------|
| 用户ID | `user_001` | 同场景一的合法用户 |
| 角色 | `employee` | 有权限的角色 |
| 资源 | `orders` | 有权访问的资源 |
| 操作 | `read` | 允许的操作 |
| 地理位置 | `XX` | 未知/高风险地区 |
| 失败登录次数 | `5` | 模拟暴力破解尝试 |

点击提交。

### 预期结果

- 显示 **ACCESS DENIED（访问拒绝）**
- 风险评分：**70+ 分**（高风险，红色进度条）
- 风险因素：`geo_anomaly`（地理异常）、`many_failed_logins`（多次失败登录）
- OPA 策略判定：**Deny**（因 `high_risk` 规则触发）

### 讲解要点

```
这个场景非常关键。

同样是 user_001，场景一可以访问，这里却被拒绝了。
用户身份没变、权限也够，唯一的区别是「环境上下文」。

系统检测到两个风险信号：
1. 地理位置异常 —— 可能是账号被盗、异地登录
2. 连续失败登录 —— 可能正在遭受暴力破解攻击

风险分数飙升到 70 分以上，触发了 OPA 策略中的 high_risk 规则。

这就是零信任的核心思想：「从不信任，始终验证」。
不是说你登录过一次就永远可信，每次访问都要重新评估当前环境。
```

## 场景四：中等风险（可选）

> **演示目标**：展示风险评分的连续性和动态变化。

### 操作步骤

| 字段 | 值 |
|------|-----|
| 地理位置 | `US` |
| 失败登录次数 | `1` |

### 预期结果

- 风险评分：**20-40 分**（中等风险，黄色进度条）
- 结果可能是 Allow 或 Deny，取决于是否达到阈值

### 讲解要点

```
这里展示的是中等风险场景。
美国不是高危地区，1次失败登录也不算严重，但分数有所上升。

在实际生产环境中，这种情况通常会触发二次认证（MFA）。
本演示简化了这部分，主要展示分数的动态变化能力。
```

## 总结话术

> 答辩时可以用这段话收尾

```
通过以上四个场景，我们可以看到这个系统的核心设计理念：

1. 「策略驱动」—— OPA 负责硬性的权限边界，谁能访问什么资源
2. 「风险感知」—— Risk Service 负责软性的环境评估，当前访问是否可信
3. 「动态决策」—— 两者结合，每次访问都实时计算，而不是静态授权

传统系统只看「你是谁」，我们还要看「你在哪、你怎么来的、之前有没有异常」。

这就是零信任架构的核心：从不信任，始终验证。
```

## 风险评分规则速查

| 风险因子 | 触发条件 | 加分 |
|----------|----------|------|
| `many_failed_logins` | 失败登录 > 3 次 | +20~40 |
| `geo_anomaly` | 地理位置非 CN | +20 |
| `privileged_action` | admin 操作或角色 | +20 |
| `missing_ua` | 无 User-Agent | +10 |
| `night_time` | 22:00-06:00 访问 | +10 |

**阈值**：分数 >= 70 触发 `high_risk`，OPA 自动拒绝。
