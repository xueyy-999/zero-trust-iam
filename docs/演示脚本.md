# 🎓 零信任 IAM 系统 - 答辩演示剧本

本文档旨在辅助毕业设计答辩，指导如何使用 Web Portal 演示系统的核心功能（ABAC 鉴权、风险评估、动态访问控制）。

## 🌐 访问地址
- **Web Portal (演示控制台)**: `http://192.168.76.129:30081`
- **Keycloak (身份源)**: `http://192.168.76.129:30080` (账号: admin / admin123)

---

## 🎬 演示场景 1：正常访问 (Happy Path)
**目标**: 展示系统在低风险、合规情况下的自动放行。

1. **操作步骤**:
   - 打开控制台首页。
   - **用户ID**: `user_001`
   - **角色**: `employee`
   - **资源**: `orders`
   - **操作**: `read` (读取)
   - **环境信息**:
     - IP: `10.2.5.100` (内网段)
     - 地理位置: `CN`
     - 失败登录次数: `0`
   - 点击 **"🚀 发起访问控制评估"**。

2. **预期结果**:
   - 界面显示 **✅ ACCESS GRANTED (访问允许)**。
   - 风险评分较低（例如 0-10 分）。
   - 策略引擎判定为 Allow。

---

## 🎬 演示场景 2：基于属性的访问控制 (ABAC - 角色/资源限制)
**目标**: 展示 OPA 策略如何根据属性（角色、操作类型）进行拦截。

1. **操作步骤**:
   - 回到首页。
   - **用户ID**: `user_002`
   - **角色**: `intern` (实习生)
   - **资源**: `financial` (财务报表)
   - **操作**: `write` (写入 - 实习生通常无权修改财务)
   - **环境信息**: 保持默认 (CN, IP正常)。
   - 点击提交。

2. **预期结果**:
   - 界面显示 **🚫 ACCESS DENIED (访问拒绝)**。
   - 风险评分可能很低（因为环境是安全的），但 **Policy Decision** 明确显示 `DENY`。
   - 可以在答辩时解释：即使环境安全，权限不足也会被 OPA 拦截。

---

## 🎬 演示场景 3：高风险环境拦截 (Risk-Based Access Control)
**目标**: 展示风险引擎如何根据环境上下文（异地登录、异常时间、暴力破解迹象）动态计算分数并拦截。

1. **操作步骤**:
   - 回到首页。
   - **用户ID**: `user_001` (合法用户)
   - **角色**: `employee` (有权限)
   - **资源**: `orders`
   - **操作**: `read`
   - **修改环境参数** (模拟黑客攻击):
     - **地理位置**: `XX` (未知/高风险区域)
     - **失败登录次数**: `5` (模拟暴力破解尝试)
   - 点击提交。

2. **预期结果**:
   - 界面显示 **🚫 ACCESS DENIED (访问拒绝)**。
   - **Risk Score** 飙升（例如 >70 分），进度条变红。
   - **风险因素**区域显示：`🔥 geo_anomaly` (地理位置异常), `🔥 many_failed_logins` (多次登录失败)。
   - 解释：虽然用户身份合法且有权限，但由于当前环境风险过高，系统动态触发了拦截策略。

---

## 🎬 演示场景 4：中等风险与 MFA (可选/进阶说明)
**目标**: 展示系统对中等风险的精细化处理（如果策略中有定义，通常是需要二次认证，这里演示分数值变化）。

1. **操作步骤**:
   - **地理位置**: `US` (非本地，但非高危)
   - **失败登录次数**: `1`
   - 点击提交。

2. **预期结果**:
   - 界面可能显示 **⚠️ 中风险** (黄色进度条)。
   - 结果取决于具体 Rego 策略阈值（通常 60 分以上拦截）。展示分数的变化体现了风险评估的动态性。
