## 一、系统架构概述

### 1.1 架构设计原则

1. **微服务架构**：各组件独立部署，松耦合设计
2. **零信任原则**：永不信任，始终验证
3. **容器化部署**：基于Kubernetes的容器编排
4. **自动化运维**：基于Ansible的自动化部署
5. **可扩展性**：模块化设计，易于扩展

### 1.2 技术栈选型

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| **容器编排** | Kubernetes 1.28+ | 容器编排平台 |
| **容器运行时** | containerd | 轻量级容器运行时 |
| **网络插件** | Flannel | CNI网络插件 |
| **身份认证** | Keycloak 23+ | OIDC/OAuth2认证服务器 |
| **授权引擎** | OPA 0.60+ | 策略引擎 |
| **风险评估** | Go 1.22 | 自研微服务 |
| **Web门户** | Go (html/template) | SSR前端 |
| **数据库** | MySQL 8.0 | 关系型数据库 |
| **自动化部署** | Ansible 2.15+ | 配置管理工具 |

## 三、核心组件设计

### 3.1 Keycloak (身份认证)

**职责：**
- 用户身份认证
- OIDC协议支持
- JWT令牌生成和验证
- 用户信息管理

**技术规格：**
- 镜像：`quay.io/keycloak/keycloak:23.0`
- 端口：8080
- 协议：OIDC/OAuth2
- 存储：内存模式（开发）/ PostgreSQL（生产）

**配置参数：**
```yaml
环境变量:
  KEYCLOAK_ADMIN: admin
  KEYCLOAK_ADMIN_PASSWORD: admin123
  KC_HTTP_ENABLED: "true"
  KC_HOSTNAME_STRICT: "false"
```

**API端点：**
- `/realms/{realm}/.well-known/openid-configuration` - OIDC配置
- `/realms/{realm}/protocol/openid-connect/token` - 令牌端点
- `/realms/{realm}/protocol/openid-connect/auth` - 授权端点

### 3.2 Risk Service (风险评估)

**职责：**
- 实时风险评分
- 多维度风险分析
- RESTful API服务

**技术规格：**
- 语言：Go 1.22
- 框架：net/http (标准库)
- 端口：8080
- 协议：HTTP/JSON

**评分算法：**

```go
func computeScore(req ScoreRequest) (int, []string) {
    score := 0
    reasons := []string{}
    
    // 1. 失败登录检查
    if req.FailedLoginCount > 3 {
        score += min(20 + req.FailedLoginCount*5, 40)
        reasons = append(reasons, "many_failed_logins")
    }
    
    // 2. 地理位置检查
    if req.Geo != "CN" && req.Geo != "" {
        score += 20
        reasons = append(reasons, "geo_anomaly")
    }
    
    // 3. 特权操作检查
    if req.Action == "admin" || contains(req.Roles, "admin") {
        score += 20
        reasons = append(reasons, "privileged_action")
    }
    
    // 4. User-Agent检查
    if req.UserAgent == "" {
        score += 10
        reasons = append(reasons, "missing_ua")
    }
    
    // 5. 时间段检查
    if hour >= 22 || hour < 6 {
        score += 10
        reasons = append(reasons, "night_time")
    }
    
    // 归一化到 [0, 100]
    score = max(0, min(100, score))
    return score, reasons
}
```

**API端点：**
- `GET /health` - 健康检查
- `POST /score` - 风险评分

### 3.3 OPA (授权决策)

**职责：**
- 授权策略执行
- ABAC访问控制
- 动态策略更新

**技术规格：**
- 镜像：`openpolicyagent/opa:0.60.0`
- 端口：8181
- 策略语言：Rego

**授权策略：**

```rego
package authz

default allow = false

# 允许读取订单（低风险）
allow {
  input.action == "read"
  input.resource == "orders"
  not high_risk
}

# 允许管理员操作（需要admin角色且低风险）
allow {
  input.action == "admin"
  roles_contains("admin")
  not high_risk
}

# 高风险定义
high_risk {
  input.score >= 70
}

# 角色检查
roles_contains(r) {
  some i
  input.roles[i] == r
}
```

**API端点：**
- `POST /v1/data/authz/allow` - 授权决策
- `PUT /v1/policies/{id}` - 更新策略
- `GET /health` - 健康检查

### 3.4 Web Portal (用户界面)

**职责：**
- 用户交互界面
- OIDC登录集成
- 请求转发和结果展示

**技术规格：**
- 语言：Go 1.22
- 模板引擎：html/template
- 端口：8081
- 渲染方式：服务端渲染(SSR)

**功能模块：**
1. **登录模块**：OIDC登录流程
2. **评估模块**：风险评估表单
3. **结果模块**：评估结果展示

**路由设计：**
```go
/              - 首页（评估表单）
/login         - OIDC登录
/callback      - OIDC回调
/logout        - 退出登录
/check         - 提交评估请求
/health        - 健康检查
```

## 五、数据流设计

### 5.1 认证流程

```
1. 用户访问 Web Portal
   │
   ▼
2. 重定向到 Keycloak 登录页
   │
   ▼
3. 用户输入凭证
   │
   ▼
4. Keycloak 验证凭证
   │
   ▼
5. 生成 JWT 令牌
   │
   ▼
6. 重定向回 Web Portal (带 code)
   │
   ▼
7. Web Portal 用 code 换取 access_token
   │
   ▼
8. 存储 session，用户登录成功
```

### 5.2 授权流程

```
1. 用户提交访问请求
   │
   ▼
2. Web Portal 调用 Risk Service
   POST /score
   {userId, roles, resource, action, ...}
   │
   ▼
3. Risk Service 计算风险分数
   返回 {score: 35, reasons: [...]}
   │
   ▼
4. Web Portal 调用 OPA
   POST /v1/data/authz/allow
   {sub, roles, resource, action, score}
   │
   ▼
5. OPA 执行策略
   - 检查角色
   - 检查风险分数
   - 返回 {result: true/false}
   │
   ▼
6. Web Portal 展示结果
   - 允许访问 / 拒绝访问
   - 显示风险分数和原因
```

## 六、安全设计

### 6.1 认证安全

1. **OIDC协议**：标准化的身份认证协议
2. **JWT令牌**：签名验证，防止篡改
3. **令牌过期**：设置合理的过期时间
4. **HTTPS传输**：加密传输（生产环境）

### 6.2 授权安全

1. **最小权限原则**：默认拒绝，显式授权
2. **动态授权**：基于实时风险评分
3. **策略隔离**：OPA策略独立管理
4. **审计日志**：记录所有授权决策

### 6.3 数据安全

1. **密码加密**：MySQL密码加密存储
2. **网络隔离**：MySQL仅ClusterIP访问
3. **持久化存储**：PVC数据持久化
4. **备份恢复**：定期备份（待实现）

### 6.4 容器安全

1. **非root用户**：容器以非特权用户运行
2. **最小镜像**：使用distroless基础镜像
3. **资源限制**：CPU和内存限制
4. **健康检查**：liveness和readiness探针
